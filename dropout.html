Dropout randomly switches off a fraction of neurons on every training step, so the network can't lean on any single unit. Flip the mask, watch activations vanish and rescale, see why the expectation is preserved — then lock it in on the Practice tab.

01 What is dropout?

The one-line idea randomly zero activations

On each forward pass during training, every neuron is independently kept with probability $1-p$ or set to zero with probability $p$ (the "drop probability"). A different random subset is dropped every step.

$$m_i \sim \text{Bernoulli}(1-p), \qquad \tilde h_i = m_i \, h_i$$
$h_i$ = activation of neuron $i$ · $m_i \in \{0,1\}$ = random mask · $p$ = drop probability
Why on earth would you delete neurons? If a unit can always rely on a specific partner to fix its mistakes, the two co-adapt and the network memorises instead of generalising. Randomly removing units forces every neuron to be useful on its own — a powerful, almost-free regulariser.

Two phases — train vs. eval

$$\textbf{train:}\;\; \tilde h = \frac{m \odot h}{1-p}$$
mask on · rescale so the expected output is unchanged
$$\textbf{eval:}\;\; \tilde h = h$$
dropout is the identity — nothing is dropped
Forgetting to switch a PyTorch model to model.eval() at inference is a classic bug: dropout stays on and your predictions become random. Always toggle train() / eval().

Where it sits in a network

# a typical block — dropout after the activation

03 Inverted dropout — keep the scale honest

Rescale during training what frameworks actually do

If we drop a fraction $p$ of units, the surviving activations are too weak on average. Inverted dropout divides the kept units by $1-p$ during training, so the expected output equals the original — and test time needs no changes at all.

$$\tilde h_i = \frac{m_i \, h_i}{1-p}, \qquad \mathbb{E}[\tilde h_i] = \frac{(1-p)\,h_i}{1-p} = h_i$$
The $1-p$ in the denominator exactly cancels the $1-p$ chance of survival.
Why "inverted"? The original 2014 paper scaled down at test time (multiply by $1-p$). Frameworks flipped it: scale up at train time instead. Same expectation, but inference is left as a clean identity — faster and bug-resistant.

04 Why it works

An ensemble of exponentially many networks ensemble view

Each dropout mask defines a different "thinned" sub-network sharing the same weights. A layer of $n$ neurons has $2^n$ possible on/off patterns — training with dropout approximately trains all of them at once and averages them at test time.

$$\#\text{sub-networks} = 2^{\,n}$$
$n$ = number of units that can be dropped

At test time we don't sample — we use the full network with all units present (scaled). That single pass is a cheap approximation to averaging the whole ensemble, which is exactly what makes ensembles generalise.

Breaking co-adaptation

Without dropout, neurons form fragile cliques: unit A learns to correct a quirk of unit B, which only works if B is present. Drop B at random and A must instead learn a feature that stands on its own.

Without dropout
• neurons co-adapt
• brittle, memorises noise
• big train/val gap (overfit)
With dropout
• redundant, robust features
• acts like an ensemble
• smaller train/val gap
Dropout adds noise, so the training loss is usually higher/noisier — but the validation loss is lower. That widening-then-closing gap is the whole point.

Cousins & cautions

DropConnect — drop individual weights instead of whole activations.
Spatial / 2D dropout — drop entire feature maps in CNNs.
DropPath / stochastic depth — drop whole residual blocks.

05 In code — PyTorch

nn.Dropout in a module

import torch.nn as nn

class MLP(nn.Module):
  def __init__(self):
    self.fc1 = nn.Linear(784, 256)
    self.drop = nn.Dropout(p=0.5) # inverted dropout, built in
    self.fc2 = nn.Linear(256, 10)

  def forward(self, x):
    x = torch.relu(self.fc1(x))
    x = self.drop(x) # active only in training mode
    return self.fc2(x)
nn.Dropout already implements inverted dropout and reads the module's mode flag. You never rescale by hand — you just flip the model between train() and eval().

The mode switch that matters

model.train() # dropout ON → masks + rescale
out = model(x)
loss.backward()

model.eval() # dropout OFF → identity pass
with torch.no_grad():
  preds = model(x) # deterministic, full network
If validation accuracy is weirdly noisy or worse than training, the #1 suspect is a missing model.eval() — dropout (and BatchNorm) are still in training mode.

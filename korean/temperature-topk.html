Temperature
& Top-k

다음 토큰이 무엇이 될지 결정하는 두 개의 다이얼. 온도(temperature)는 확률 곡선 전체를 다시 빚어낸다 — 차갑고 확신에 찬 분포로, 또는 뜨겁고 거친 분포로. Top-k는 쓸모없는 긴 꼬리를 버리고 가장 좋은 k개 후보만 남긴다. 슬라이더를 드래그하고, 토큰을 샘플링하며, 분포가 숨 쉬는 모습을 지켜보자.

1이 다이얼이 필요한 이유

언어 모델의 마지막 레이어는 어휘(vocabulary)의 모든 토큰에 대해 로짓(logit)을 만든다 — 수만 개의 원시 점수다. 소프트맥스(softmax)는 이를 “다음에 무엇이 올지”에 대한 확률 분포로 바꾼다. 하지만 순수한 소프트맥스 샘플링에는 문제가 있고, 이 두 다이얼이 그 문제를 해결한다.

그리디(greedy)의 함정

항상 확률이 가장 높은 단일 토큰(argmax)만 고르는 것은 결정적이고 안전하지만, 밋밋하고 반복적이며 생기 없는 텍스트를 만들고 루프에 빠진다(“the the the”). 실제 생성에는 통제된 무작위성이 필요하다.

온도(Temperature)는 무작위성을 얼마나 줄지 정하는 다이얼이다.

긴 꼬리(long-tail)의 함정

5만 개 토큰의 어휘란, 수만 개의 토큰이 각각 아주 작은 확률을 갖는다는 뜻이다. 합치면 이 쓰레기 꼬리가 실제로 무시 못 할 확률 질량을 가질 수 있고, 가끔은 문장 전체를 탈선시키는 엉뚱한 토큰을 뽑게 된다.

Top-k(그리고 사촌인 top-p)는 주사위를 굴리기 전에 꼬리를 잘라내는 필터다.

멘탈 모델: 온도는 곡선을 다시 빚고, top-k는 곡선을 잘라낸다. 실제 모든 샘플러에서 둘은 함께 적용된다 — 온도가 먼저, 그다음 잘라내기, 그다음 무작위 추출.

2온도(Temperature) — 로짓 다시 스케일링하기

τ는 소프트맥스 전에 로짓을 나눈다

$$p_i \;=\; \frac{e^{\,z_i/\tau}}{\sum_j e^{\,z_j/\tau}}$$

하나의 스칼라 $\tau>0$가 지수 함수를 취하기 전에 모든 로짓을 나눈다. 소프트맥스는 로짓의 차이에 의존하므로, $\tau$로 나누면 모든 격차가 같은 비율로 늘어나거나 줄어든다.

  • $\tau \to 0^{+}$ — 격차가 폭발적으로 커지고, 최상위 로짓이 모든 것을 가져간다. 분포는 argmax에서의 원-핫(one-hot)으로 붕괴한다. 이것이 순수한 그리디(greedy) 디코딩이다.
  • $\tau = 1$ — 모델 자신의, 손대지 않은 분포.
  • $\tau \to \infty$ — 모든 $z_i/\tau \to 0$이 되어 지수 값이 전부 같아진다. 분포는 균등(uniform) $1/V$가 된다. 최대의 혼돈.

차가움 vs 뜨거움, 직관적으로

이 이름은 통계 물리학에서 왔다 — 볼츠만 분포 $p_i \propto e^{-E_i/kT}$의 바로 그 온도다.

  • 낮은 τ (≈0.2–0.7) — 집중되고, 결정적이며, “확신에 찬” 분포. 코드, 수학, 사실 기반 답변에 좋다.
  • 높은 τ (≈1.0–1.5) — 다양하고, 놀랍고, “창의적인” 분포. 브레인스토밍, 시, 이야기 아이디어에 좋다. 너무 높으면 → 횡설수설.

실험실에서 직접 확인하게 될 핵심 사실: 온도는 확률을 다시 빚을 뿐, 토큰의 순위(ranking)는 절대 바꾸지 않는다. 양수로 나누는 것은 단조(monotonic) 연산이기 때문이다.

⬇ 온도를 드래그하라 — 로짓 9개는 매번 똑같고, τ만 바뀐다. 뾰족한 봉우리가 평평한 고원으로 녹아내리고, 막대가 파랑에서 빨강으로 달궈지는 모습을 지켜보자.

3Top-k — 상위 k개만 남기고 나머지는 버린다

알고리즘

  1. 토큰을 로짓 기준 내림차순으로 정렬한다.
  2. 상위 k개를 남긴다. 나머지 모든 로짓을 $-\infty$로 설정한다.
  3. 살아남은 토큰들에만 소프트맥스를 다시 돌려, 남은 확률이 합이 1이 되도록 재정규화(renormalize)되게 한다.
  4. 이 잘린 분포에서 샘플링한다.
$$p^{\text{top-}k}_i = \begin{cases}\dfrac{e^{z_i/\tau}}{\sum_{j\in K} e^{z_j/\tau}} & i \in K\\[6pt] 0 & \text{otherwise}\end{cases}$$

$K$ = 로짓이 가장 큰 $k$개의 인덱스 집합.

무엇을 얻는가

  • 쓰레기 꼬리를 없앤다. 확률이 거의 0인 수천 개의 토큰은 아무리 운이 나빠도 절대 샘플링되지 않는다.
  • k = 1은 정확히 그리디(greedy) 디코딩이다(최상위 토큰만 살아남는다).
  • k = 어휘 크기는 잘라내기를 끈다 — 평범한 (온도로 스케일링된) 소프트맥스로 돌아간다.
  • 전형적인 값: 개방형 텍스트엔 k = 40, 집중된 작업엔 더 작게.

순서는 중요하지만 살아남는 집합은 τ에 의존하지 않는다. $z/\tau$는 $z$와 같은 순위를 유지하므로, top-k에 든 토큰은 어떤 온도에서도 그대로 top-k에 남는다 — 움직이는 것은 그들 사이의 상대적 비중뿐이다.

4그래프 — τ가 곡선을 어떻게 휘게 하는가

온도를 전체 범위에 걸쳐 훑어보자(8개 토큰 전부, 잘라내기 없음). τ가 올라가면 승자의 확률은 떨어지고, 엔트로피는 균등 분포의 최댓값을 향해 올라간다. 점선은 실험실에서 설정한 현재 τ를 표시한다.

P(최상위 토큰) — 차가우면 솟고, 뜨거우면 평평해진다 정규화된 엔트로피 — 0 = 확실, 1 = 균등 현재 τ

두 곡선이 교차하는 것에 주목하자: 단 하나의 “최고의” 온도란 없다 — 확신과 다양성 사이의 절충이다. 그 절충이 바로 디코딩의 모든 기술이다.

5Top-k vs top-p(뉴클리어스) vs 온도

서로 다른 일을 한다

  • 온도 — 분포를 다시 빚는다. 얼마나 뾰족한지 평평한지를 바꾼다. 어떤 토큰도 제거하지 않는다.
  • Top-k — 고정된 개수로 잘라낸다. 모델이 아무리 확신하더라도 항상 정확히 k개 토큰만 남긴다.
  • Top-p(뉴클리어스) — 누적 확률로 잘라낸다. 확률 합이 ≥ p가 되는 가장 작은 집합을 남긴다. 개수가 적응한다: 확신할 땐 적은 토큰, 불확실할 땐 많은 토큰.

실제 파이프라인

실전 샘플러는 이 순서로 이들을 연결한다:

  1. 온도 적용: $z \leftarrow z/\tau$.
  2. top-k 및/또는 top-p 잘라내기 적용(탈락자를 $-\infty$로 마스킹).
  3. 생존자에 소프트맥스 → 재정규화.
  4. 토큰 하나를 고른다: 분포에서 샘플링(무작위, 창의적)하거나, argmax를 취한다 — 확률이 가장 높은 단일 생존자(그리디, 결정적).

바로 그 마지막 단계가 갈림길이다: argmax는 항상 최상위 토큰을 내보내므로, 같은 프롬프트는 항상 같은 단어를 준다. 샘플링은 남은 막대들에 선택을 분산시킨다. 실험실의 👑 Argmax 버튼을 눌러보자 — 몇 번을 눌러도 왕관 쓴 토큰에 고정되는 반면, 🎲 샘플은 이리저리 떠돈다.

Top-k의 약점: 고정된 k는 모델이 확신할 때(명백한 토큰 1개 + 나쁜 토큰 39개)는 너무 후하고, 모델이 갈팡질팡할 때(좋은 선택지가 많을 때)는 너무 엄격하다. Top-p는 개수를 적응시켜 이를 해결한다 — 그래서 오늘날 뉴클리어스 샘플링이 더 흔한 기본값이다.

6실제 모델은 무엇을 쓰는가 — 샘플링인가 argmax인가?

둘 다 모델의 일부가 아니다. 트랜스포머는 오직 로짓만 출력한다; 샘플링이냐 argmax냐는 추론 시점에 애플리케이션이 내리는 디코딩 선택이다(그리고 학습과는 무관하다). 사용 사례를 골라 전형적인 설정을 살펴보자.

temperature = 0 ⇒ argmax

대부분의 API에서 temperature = 0으로 설정하는 것은 정확히 그리디 디코딩이다. τ→0이 되면 최상위 로짓이 모든 질량을 가져가므로, 모델은 매번 자신의 argmax를 내보낸다 — 결정적이고 재현 가능한 출력이다. 매 실행마다 같은 답이 필요할 때 사용하라(테스트, 구조화된 추출, 사실 조회).

이것이 argmax 아래에서 온도가 죽은 다이얼이 되는 이유다(실험실에서 직접 확인했다): τ로 나눠도 순위는 절대 바뀌지 않으므로, 승자도 절대 바뀌지 않는다.

빔 서치(beam search) — 세 번째 선택지

argmax처럼 결정적이지만, 단일 최선의 다음 토큰을 탐욕적으로 취하는 대신 여러 후보 시퀀스(“빔”)를 살려두고 가장 가능성 높은 문장 전체를 반환한다. 전역적 유창성이 중요한 번역과 요약에 강하다.

개방형 대화에는 거의 쓰이지 않는다 — 안전하고 일반적이며 다양성이 낮은 텍스트를 만드는 경향이 있다. 그쪽에서는 샘플링이 이긴다.

한 줄 요약: 창의적 / 대화형 → 샘플링(온도 + top-p), 현대의 기본값 · 정확성 / 재현성 → argmax(온도 0) 또는 낮은 온도 · 번역 / 요약 → 빔 서치.

7코드로 보기

import torch import torch.nn.functional as F def sample_next(logits, temperature=1.0, top_k=40): # logits: (vocab,) 모델에서 나온 원시 점수 # 1) 온도 — 소프트맥스 전에 로짓을 나눈다 logits = logits / max(temperature, 1e-6) # 2) top-k — 상위 k개를 남기고 나머지는 -inf로 마스킹 if top_k is not None: kth = torch.topk(logits, top_k).values[-1] # k번째로 큰 로짓 logits = logits.masked_fill(logits < kth, float("-inf")) # 3) 생존자에 소프트맥스 -> 재정규화된 확률 probs = F.softmax(logits, dim=-1) # 4) 범주형 분포에서 토큰 하나를 뽑는다 return torch.multinomial(probs, num_samples=1)

temperature는 소프트맥스 전에 나누고, 로짓의 -inf는 소프트맥스 후 정확히 0이 된다는 점에 주목하자 — 그래서 마스킹된 토큰은 절대 샘플링되지 않는다. top_k=1로 설정하면 그리디 argmax로 축소되고, temperature→0도 같은 일을 한다.

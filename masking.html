Section 3.2.3 · forbidding connections

Masking — blocking attention

Self-attention lets every token look at every other token. Sometimes that's wrong: a decoder must not peek at future words it hasn't generated yet, and no token should waste attention on <pad> filler. A mask forbids those connections by forcing their attention weight to exactly zero — implemented by adding −∞ to the scores before the softmax.

01 Two masks, one mechanism

causal · look-ahead

No peeking forward

In the decoder's self-attention, token i may attend only to positions ≤ i. This preserves the auto-regressive property: prediction of the next token can't depend on tokens that come after it. The mask is a lower-triangular matrix.

padding

Ignore the filler

Batching sequences of different lengths pads the short ones with <pad>. The padding mask blanks out those key positions so attention never spends weight on meaningless tokens — for every query, in encoder and decoder alike.

The paper's words: "We … implement [masking] inside of scaled dot-product attention by masking out (setting to −∞) all values in the input of the softmax which correspond to illegal connections." The mask never changes the data — it only deletes the edges of the attention graph.

Inside scaled dot-product attention

Where the mask lives

The mask is applied at exactly one spot: on the raw attention scores QKᵀ/√d, after the scale and before the softmax. Add a matrix M that is 0 for allowed pairs and −∞ for forbidden ones.

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}} + M\right)V, \qquad M_{ij} = \begin{cases} 0 & \text{allowed} \\ -\infty & \text{masked} \end{cases}$$
the pipeline · where M enters
Q·Kᵀ [T, T] → ÷ √d + M [T, T] → softmax → weights [T, T]

Because e^{-\infty} = 0, every masked entry contributes zero to the softmax — and the surviving weights renormalize to sum to 1. The value matrix V is never touched by the mask.

scaled dot-product attention, with mask 
def attention(Q, K, V, mask=None):           # Q,K,V: [B, H, T, d_k]
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)   # [B, H, T, T]
    if mask is not None:                       # mask: True = keep
        scores = scores.masked_fill(mask == 0, float('-inf'))
    attn = scores.softmax(dim=-1)              # masked → 0
    return attn @ V                            # [B, H, T, d_k]
Why -inf, not just a small number? A finite penalty would still leak a little probability through. -inf (in practice a large negative like -1e9) guarantees the softmax output is exactly 0 there.
The look-ahead mask

Causal — lower triangular

Rows are queries (the token doing the looking), columns are keys (the tokens being looked at). A query at position i may attend only to keys j ≤ i — so the allowed region is the lower triangle, including the diagonal. Drag the query slider and watch its window of visible keys grow.

Read it: position 0 sees only itself; the last position sees everything. Each step down the diagonal opens exactly one more key. The upper triangle — the future — is always blocked.
building the causal mask 
mask = torch.tril(torch.ones(T, T)).bool()   # [T, T], True on/below diagonal
# row i (query) is True for cols 0..i, False for the future
scores = scores.masked_fill(~mask, float('-inf'))

The key identity: $\;\mathrm{softmax}(z)_k = \dfrac{e^{z_k}}{\sum_j e^{z_j}}$, and $e^{-\infty}=0$. So a masked logit drops out of both the numerator and the denominator — the remaining weights always still sum to 1.
Masking in multi-head attention

One mask, every head

Multi-head attention runs H attention computations in parallel, each with its own Q, K, V projection — so the scores have shape [B, H, T, T]. The mask depends only on token positions, not on the head, so a single mask of shape [B, 1, T, T] (or [1, 1, T, T] for a pure causal mask) is broadcast across all H heads. Same forbidden cells, H different attention patterns.

broadcasting the mask over heads 
scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)   # [B, H, T, T]
causal = torch.tril(torch.ones(T, T)).bool()        # [T, T]
scores = scores.masked_fill(~causal, float('-inf')) # [T,T] broadcasts over B, H
attn = scores.softmax(dim=-1)                        # each head normalized separately
Why it broadcasts cleanly: the rule "can position i see position j?" is a property of the sequence, identical for every head and every example in the batch. So the mask carries no head axis — NumPy/PyTorch broadcasting stretches the lone [T, T] across the [B, H, …] dimensions for free.
Ignoring <pad> tokens

The padding mask

To batch sentences of different lengths, the short ones are padded to a common length with <pad>. Those positions carry no meaning, so the padding mask blanks out their key columns — for every query row. Slide the real-token count and watch the pad columns go dark.

Note the shape: a padding mask blocks whole columns (keys), so it looks like vertical stripes — unlike the causal mask's triangle. Real models often combine both: causal & padding.
building & combining masks 
pad_mask = (tokens != PAD_ID)                # [B, T]  True = real
pad_mask = pad_mask[:, None, None, :]        # [B, 1, 1, T] over keys
causal   = torch.tril(torch.ones(T, T)).bool()  # [T, T]
mask = pad_mask & causal                     # decoder self-attn uses both

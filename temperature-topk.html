1Why we need these knobs

A language model's final layer produces a logit for every token in its vocabulary — tens of thousands of raw scores. Softmax turns those into a probability distribution over “what comes next.” But raw softmax sampling has problems, and these two knobs fix them.

The greedy trap

Always taking the single highest-probability token (argmax) is deterministic and safe — but it produces flat, repetitive, lifeless text and gets stuck in loops (“the the the”). Real generation needs controlled randomness.

Temperature is the dial for how much randomness.

The long-tail trap

A 50,000-token vocabulary means tens of thousands of tokens each get a tiny probability. Summed together that junk tail can hold real mass — and occasionally you sample a nonsense token that derails the whole sentence.

Top-k (and its cousin top-p) is the filter that deletes the tail before you roll the dice.

Mental model: temperature reshapes the curve, top-k truncates it. They are applied together in every real sampler — temperature first, then truncation, then a random draw.

2Temperature — rescaling the logits

τ divides the logits before softmax

$$p_i \;=\; \frac{e^{\,z_i/\tau}}{\sum_j e^{\,z_j/\tau}}$$

One scalar $\tau>0$ divides every logit before the exponential. Because softmax depends on logit differences, dividing by $\tau$ stretches or squashes every gap by the same factor.

  • $\tau \to 0^{+}$ — gaps blow up; the top logit wins everything. Distribution collapses to a one-hot at argmax. This is pure greedy decoding.
  • $\tau = 1$ — the model's own, un-modified distribution.
  • $\tau \to \infty$ — every $z_i/\tau \to 0$, all exponentials equal. Distribution becomes uniform $1/V$. Maximum chaos.

Cold vs hot, intuitively

The name comes from statistical physics — it is the temperature in the Boltzmann distribution $p_i \propto e^{-E_i/kT}$.

  • Low τ (≈0.2–0.7) — focused, deterministic, “confident.” Good for code, math, factual answers.
  • High τ (≈1.0–1.5) — diverse, surprising, “creative.” Good for brainstorming, poetry, story ideas. Too high → incoherent.

A key fact you'll prove in the lab: temperature only reshapes probabilities — it never changes the ranking of tokens, because dividing by a positive number is monotonic.

3Top-k — keep the best k, drop the rest

The algorithm

  1. Sort tokens by logit, descending.
  2. Keep the top k. Set every other logit to $-\infty$.
  3. Re-run softmax over just the survivors so the kept probabilities renormalize to sum to 1.
  4. Sample from this truncated distribution.
$$p^{\text{top-}k}_i = \begin{cases}\dfrac{e^{z_i/\tau}}{\sum_{j\in K} e^{z_j/\tau}} & i \in K\\[6pt] 0 & \text{otherwise}\end{cases}$$

$K$ = the set of indices with the $k$ largest logits.

What it buys you

  • Kills the junk tail. The thousands of near-zero-probability tokens can never be sampled, no matter how unlucky the roll.
  • k = 1 is exactly greedy decoding (only the top token survives).
  • k = vocab size disables truncation — back to plain (temperature-scaled) softmax.
  • Typical values: k = 40 for open-ended text, smaller for focused tasks.

Order matters but the survivor set doesn't depend on τ. Since $z/\tau$ keeps the same ranking as $z$, whichever tokens are in the top-k stay in the top-k for any temperature — only their relative shares move.

5Top-k vs top-p (nucleus) vs temperature

They do different jobs

  • Temperature — reshapes the distribution. Changes how peaked vs flat it is. Doesn't remove any token.
  • Top-k — truncates by a fixed count. Always keep exactly k tokens, however confident the model is.
  • Top-p (nucleus) — truncates by cumulative probability. Keep the smallest set whose probabilities add up to ≥ p. The count adapts: few tokens when confident, many when uncertain.

The real pipeline

Production samplers chain them, in this order:

  1. Apply temperature: $z \leftarrow z/\tau$.
  2. Apply top-k and/or top-p truncation (mask the losers to $-\infty$).
  3. Softmax the survivors → renormalize.
  4. Pick one token: either sample from the distribution (random, creative) or take the argmax — the single highest-probability survivor (greedy, deterministic).

That last step is the fork: argmax always emits the top token, so the same prompt always gives the same word. Sampling spreads the choice across the kept bars. Try the 👑 Argmax button in the lab — it locks onto the crowned token no matter how many times you press it, while 🎲 Sample wanders.

Top-k's weakness: a fixed k is too generous when the model is sure (one obvious token + 39 bad ones) and too strict when it's torn (many good options). Top-p fixes that by adapting the count — which is why nucleus sampling is the more common default today.

6Which do real models use — sampling or argmax?

Neither is part of the model. The transformer only outputs logits; sampling vs argmax is a decoding choice made at inference time by the application (and it's unrelated to training). Pick a use case to see the typical setup.

temperature = 0 ⇒ argmax

In most APIs, setting temperature = 0 is exactly greedy decoding. As τ→0 the top logit takes all the mass, so the model emits its argmax every time — deterministic, reproducible output. Use it when you need the same answer on every run (tests, structured extraction, factual lookups).

This is why temperature is a dead knob under argmax (you proved it in the lab): dividing by τ never changes the ranking, so the winner never changes.

Beam search — the third option

Deterministic like argmax, but instead of greedily taking the single best next token it keeps several candidate sequences (“beams”) alive and returns the most likely whole sentence. Strong for translation & summarization where global fluency matters.

Rarely used for open-ended chat — it tends to produce safe, generic, low-diversity text. There, sampling wins.

One-line takeaway: creative / conversational → sampling (temperature + top-p), the modern default · accuracy / reproducibility → argmax (temperature 0) or low temperature · translation / summary → beam search.

7In code

import torch import torch.nn.functional as F def sample_next(logits, temperature=1.0, top_k=40): # logits: (vocab,) raw scores from the model # 1) temperature — divide logits BEFORE softmax logits = logits / max(temperature, 1e-6) # 2) top-k — keep the k largest, mask the rest to -inf if top_k is not None: kth = torch.topk(logits, top_k).values[-1] # k-th largest logit logits = logits.masked_fill(logits < kth, float("-inf")) # 3) softmax over survivors -> renormalized probabilities probs = F.softmax(logits, dim=-1) # 4) draw one token from the categorical distribution return torch.multinomial(probs, num_samples=1)

Note temperature divides before softmax, and -inf in a logit becomes exactly 0 after softmax — so masked tokens can never be sampled. Setting top_k=1 reduces this to greedy argmax; temperature→0 does the same thing.
